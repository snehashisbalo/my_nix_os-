## 1. The two configs on this machine

There are **two completely separate, overlapping NixOS configurations** on disk. Only one is real.

### `/etc/nixos/` — STALE, do not use
- Plain, non-flake `configuration.nix` + `hardware-configuration.nix`.
- Describes an **old Hyprland + Waybar** setup. It has **no `flake.nix`**.
- It is **not** what your running system was built from.
- Anything built from here would **replace Niri/Noctalia with the old Hyprland rice**.
- Leave it alone. (If you ever want, you can delete it, but nothing reads it.)

### `/etc/nixos/` — THE REAL CONFIG (flake)
- This is the flake that built every generation currently in `/nix/var/nix/profiles`.
- It produces `nixosConfigurations.compulex`.
- It uses **den + import-tree + flake-parts** to auto-import `modules/`.
- All real edits happen here.

> The old `upp` fish alias pointed at `/etc/nixos#compulex`, which has no flake and
> would fail (or activate the stale Hyprland config). It now points at
> `/etc/nixos#compulex`.

## 2. Mental model (NixOS in one screen)

NixOS is declarative: you describe the *desired end state*, and the system is
built from it. You never hand-edit files in `/etc` or `~/.config` for
configured things — you edit the `.nix` source and rebuild.

Three layers are in play:

1. **System (NixOS)** — bootloader, kernel, services, system-wide packages,
   users. Lives in `modules/aspects/**` + `modules/hosts/**`.
2. **Home Manager (HM)** — per-user dotfiles and packages
   (`~/.config/*`, `home.packages`). Runs as `home-manager-scythe.service`.
   Lives in `homeManager = { ... }` blocks and `modules/users/scythe.nix`.
3. **`nix` CLI** — for ad-hoc/imperative/dev work outside the system
   (`nix shell`, `nix develop`, `nix run`, per-project `flake.nix`).

**Golden rule:** if a file says “generated by Home Manager / DO NOT EDIT”, edit
the `.nix` that produced it instead. Hand-editing generated files causes the
famous Home Manager “would be clobbered” failure on the next rebuild.

### Rebuild commands explained
- `build` — evaluates + compiles the config, makes a `./result` symlink. **Does
  not touch your running system.** Safest way to check for errors.
- `test` — builds and activates *now*, but the boot default is unchanged. If
  something breaks, reboot into the previous generation.
- `switch` — builds, sets as the default for next boot, **and** activates now.
  This is the normal day-to-day command.
- `boot` — sets as default for next boot, does not activate now.
- `--rollback` — switch back to the previous system generation.
- NixOS generations include the Home Manager generation, so a NixOS rollback
  rolls back your dotfiles too.

### Purity: when you need `--impure`
The flake is evaluated in **pure mode**: it may only read files inside the
flake directory (and its inputs). If a `.nix` file references an absolute path
outside the repo (e.g. `/home/scythe/dots/...`), the build fails with
`access to absolute path ... is forbidden in pure evaluation mode`.
Fix by either:
- copying the file into the repo (recommended), or
- running with `nixos-rebuild ... --impure` (allowed but less reproducible).

The current config is **pure** — no `--impure` needed.

## 3. How `os/` is structured

```
os/
├── flake.nix                       # inputs + mkFlake { import-tree ./modules }
├── GUIDE.md                        # this file
├── README.md
├── patches/                        # out-of-tree patches (Noctalia C++)
├── assets/                         # images (fastfetch art, wallpapers, nvim?)
└── modules/                        # EVERYTHING here is auto-imported
    ├── parts.nix                   # flake-parts: target systems
    ├── den.nix                     # den.flakeModule + global defaults
    ├── entities/theme.nix          # named themes: palette + font/cursor/icons
    ├── hosts/compulex/
    │   ├── default.nix             # declares host + host aspect
    │   └── hardware.nix            # generated disk/CPU (do not hand-edit)
    ├── users/scythe.nix            # the scythe aspect (user + HM config)
    └── aspects/
        ├── core/       { default, common }        # nix settings, tz, base pkgs
        ├── workstation/{ default, gaming, printing, sound,
        │                 wm/{ default, fonts, graphical, gtk, keyd, session, niri/… } }
        ├── terminals/  { default, ghostty, kitty }
        ├── shell/      { default, fish, starship }
        ├── tools/      { default, git, mpv, noctalia, satty, system, vesktop, yazi }
        └── browsers/   { default, firefox }
```

### The core abstraction: an *aspect*
An **aspect** is a composable chunk of config. Shape:

```nix
{ den, ... }:
{
  den.aspects.<group>.<name> = {
    includes = [ den.aspects.something.else ];  # pull in other aspects
    nixos       = { pkgs, ... }: { /* system config */ };
    homeManager = { pkgs, ... }: { /* user config */ };
  };
}
```

- `includes` = composition/reuse.
- `nixos = { ... }: { ... }` emits into the **system**.
- `homeManager = { ... }: { ... }` emits into the **user’s home**.
- Same aspect can inject both.

`modules/aspects/<group>/default.nix` is an aggregator that `includes` the
group’s members. For example `shell/default.nix` includes `fish` and `starship`.

### How it wires together
- `modules/hosts/compulex/default.nix` declares the host and the
  `den.aspects.compulex` aspect, which `includes` `workstation.default`.
- `modules/users/scythe.nix` declares the `den.aspects.scythe` aspect, which
  `includes` `core`, `browsers`, `terminals`, `shell`, `tools`, plus den
  batteries (`define-user`, `primary-user`, `host-aspects`).
- `den.batteries.host-aspects` forwards the host’s `homeManager` keys onto the
  user.
- `den.hosts.x86_64-linux.compulex.users.scythe = { };` links the two.

**Where to put a change:**
- Machine-specific (disk, CPU, bootloader) → `hosts/compulex/`.
- Shared system service / system package → an aspect under `aspects/**`, or
  `core/common.nix` for truly global.
- User package / dotfile → `users/scythe.nix` or an aspect’s `homeManager` key.
- Rice/desktop → `aspects/workstation/wm/**` or `aspects/tools/**`.

## 4. Changing settings

### 4.1 Install a system-wide program (all users)
Add to `environment.systemPackages` in `modules/aspects/core/common.nix`:

```nix
environment.systemPackages = with pkgs; [
  ripgrep
  fd
  # ...
];
```
Then rebuild. Prefer HM when the program is just for you.

### 4.2 Install a program for your user only
Add to `home.packages` in `modules/users/scythe.nix` (inside `homeManager`):

```nix
home.packages = with pkgs; [
  ripgrep
  # ...
];
```

Rule of thumb: **user apps → HM**, **services/daemons/system libs → NixOS**.

### 4.3 Remove a program
Delete its line from the relevant list and rebuild. The old store path stays
until garbage collection. Then `sudo nix-collect-garbage -d`.

### 4.4 Enable a service / change a system setting
Add the option in the relevant aspect, e.g.:

```nix
nixos = { pkgs, ... }: {
  services.openssh.enable = true;
  services.printing.enable = true;
  boot.kernelPackages = pkgs.linuxPackages_zen;
};
```
Find option names at <https://search.nixos.org/options>.

### 4.5 Configure a program declaratively
Most programs have a Home Manager module. Prefer it over raw files:

```nix
programs.<name> = {
  enable = true;
  settings = { ... };
};
```
Examples already in the repo: `programs.fish`, `programs.kitty`,
`programs.ghostty`, `programs.yazi`, `programs.mpv`, `programs.git`,
`programs.fastfetch`, `programs.noctalia`, `programs.satty`.

### 4.6 Drop in a raw config file
For things without a module, use `xdg.configFile` / `home.file` (HM) or
`environment.etc` (system):

```nix
# user dotfile
xdg.configFile."app/config.toml".text = ''
  key = "value"
'';

# or from a file in the repo (pure-mode safe, relative path)
xdg.configFile."app/config.toml".source = ../../assets/app/config.toml;

# system file: /etc/app/config
environment.etc."app/config".text = "…";
```

To overwrite a file another module owns, use `lib.mkForce`:
```nix
xdg.configFile."app/x".force = lib.mkForce true;
```
(`force = true` also wins over leftover unmanaged files, but clean leftovers
first — see §11.1.)

### 4.7 Add a whole new aspect (most common task)
1. Create `modules/aspects/<group>/<name>.nix`:
   ```nix
   { den, ... }:
   {
     den.aspects.<group>.<name> = {
       homeManager = { pkgs, ... }: {
         home.packages = with pkgs; [ neofetch ];
       };
     };
   }
   ```
2. Add it to the group aggregator `modules/aspects/<group>/default.nix`:
   ```nix
   includes = with den.aspects.<group>; [ <name> /* … */ ];
   ```
   (If the group default doesn’t exist, or you want it only on the user, add
   `den.aspects.<group>.<name>` directly to an `includes` list in
   `users/scythe.nix` or `hosts/compulex/default.nix`.)
3. Build to verify: `nixos-rebuild build --flake /etc/nixos#compulex`.
4. `sudo nixos-rebuild switch --flake /etc/nixos#compulex`.

### 4.8 Change the theme/palette
**Noctalia is the single source of truth for colours.** A theme switch is one
command:

```bash
theme-set <name>          # e.g. theme-set catppuccin
theme-menu                # pick from a themed launcher
theme-cycle               # next theme in order
theme-current             # which theme is active
theme-reapply             # re-render without changing the palette
theme-next-wallpaper
```

Named themes live in `modules/users/scythe.nix` under `theme.themes`. Each one
selects a Noctalia palette (`palette.kind` + `palette.name`), an optional
`wallpaper`, and may override the global `theme.font` / `theme.cursor` /
`theme.icons`.

Every theme is **dark**: the `mode` option only accepts `"dark"`, so setting
`"light"` fails at build time and there are no light palettes or light
cursor/icon overrides in the config.

What a switch changes, live:

- **Colours** — Noctalia re-renders every enabled template: kitty, ghostty,
  GTK 3/4, Qt, btop, cava, niri, plus the repo user templates for starship,
  mpv, yazi, fastfetch, vesktop and neovim (see
  `modules/aspects/workstation/theme/templates/`).
- **Font / cursor / icons** — written by `theme-runtime-apply` into
  `~/.config/gtk-{3,4}.0/settings.ini`, `~/.config/fontconfig/fonts.conf`,
  `~/.config/xsettingsd/xsettingsd.conf`, `~/.local/share/icons/default/` and
  `~/.config/niri/theme.kdl` (niri reloads the include without a re-login).

Every font/cursor/icon package a theme names is built into the store, so
switching never needs a rebuild. Home Manager deliberately does **not** own
`gtk-*/settings.ini` (the `gtk` module is off) because a store symlink could
not be rewritten at runtime.

Fastfetch art is `assets/fastfetch/Easy.png`.

### 4.9 Add a package from another flake / overlay
`flake.nix` already has inputs (`noctalia`, `spicetify-nix`,
`nixpkgs-satellite`, …). Reference them in a module via the `inputs` argument
(available because `den.batteries.inputs'` is active):
```nix
{ inputs, pkgs, ... }:
{ ... inputs.noctalia.packages.${pkgs.stdenv.hostPlatform.system}.default ... }
```
For `allowUnfree`, it’s already globally on (`nixpkgs.config.allowUnfree = true`).

## 5. Build / apply / roll back

```bash
# from anywhere (absolute path)
nixos-rebuild build --flake /etc/nixos#compulex      # check only
sudo nixos-rebuild test  --flake /etc/nixos#compulex # try now
sudo nixos-rebuild switch --flake /etc/nixos#compulex   # <-- normal
sudo nixos-rebuild boot  --flake /etc/nixos#compulex # next boot
```

- **Roll back everything:** `sudo nixos-rebuild switch --rollback`
- **List generations:** `sudo nixos-rebuild list-generations`
- **Boot menu:** systemd-boot lists old generations; pick one at boot.
- **Home Manager only:** HM is a NixOS module here, so use the NixOS
  generation commands above. (`home-manager` CLI is not installed.)

Build output goes to `./result` and `./result-*`; they are symlinks into
`/nix/store` and are **not** tracked artifacts.

## 6. Dev environments (Python, C/C++, Rust)

Nix gives you three levels of isolation. `programs.nix-ld` is **enabled** on
this machine, so prebuilt/foreign binaries (rustup toolchains, manylinux
wheels, downloaded executables) also work.

### 6.1 Ad-hoc: `nix shell` / `nix run` / `nix-shell`
Nothing is installed permanently; dropped when the shell exits.
```bash
nix shell nixpkgs#cargo nixpkgs#rustc        # interactive shell
nix shell nixpkgs#hello -c hello             # run one command
nix run nixpkgs#cowsay -- "moo"              # run an app
nix-shell -p python3 python3Packages.numpy   # classic old-style shell
```
A specific nixpkgs branch/revision:
`nix shell github:NixOS/nixpkgs/nixos-24.11#gcc`.

### 6.2 Per-project: `nix develop` + a `flake.nix`
This is the recommended, reproducible approach. Create `flake.nix` in the
project root:

```nix
{
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  outputs = { self, nixpkgs }:
    let
      system = "x86_64-linux";
      pkgs = nixpkgs.legacyPackages.${system};
    in {
      devShells.${system}.default = pkgs.mkShell {
        packages = with pkgs; [ gcc gdb gnumake cmake pkg-config ];
        shellHook = ''echo "C/C++ shell ready"'';
      };
    };
}
```
Then:
```bash
nix develop                  # enter the shell
nix develop -c make          # run a command in it
nix develop -c bash          # bash inside
```
Commit `flake.lock` to pin exact versions. Two projects can use completely
different toolchains with zero conflict.

### 6.3 Automatic activation: direnv + nix-direnv
Add once (HM) to auto-enter/exit dev shells when you `cd` into a project:
```nix
# in modules/users/scythe.nix (homeManager block) or a shell aspect
programs.direnv = {
  enable = true;
  nix-direnv.enable = true;
};
```
Then per project: `echo "use flake" > .envrc && direnv allow`.

### 6.4 Python
- **Quick & throwaway:** `nix-shell -p python3Packages.requests` then `python -c …`
- **Reproducible deps via devShell:**
  ```nix
  packages = [
    (pkgs.python3.withPackages (ps: with ps; [ numpy pandas requests ]))
  ];
  ```
- **venv/pip works on this machine** (verified: `ensurepip` is present, nix-ld
  handles binary wheels):
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  pip install -r requirements.txt
  ```
  Caveat: keep Nix-provided and pip-provided deps from colliding; install
  system-level native libs through Nix, Python packages through pip/venv.
- Python here is `3.14.7`, provided by `home.packages` (`~/.nix-profile/bin/python3`).

### 6.5 C / C++
```nix
packages = with pkgs; [
  gcc clang gdb gnumake cmake pkg-config ninja ccache
];
```
```bash
nix develop -c bash
g++ -std=c++20 -O2 main.cpp -o main
```
One-off without a shell:
```bash
nix shell nixpkgs#gcc -c bash -c 'g++ main.cpp -o main && ./main'
```

### 6.6 Rust
```nix
packages = with pkgs; [
  rustc cargo clippy rustfmt rust-analyzer
];
```
```bash
cargo new hello && cd hello
cargo run
```
Need nightly / multiple toolchains? Use `rustup` (works because `nix-ld` is on):
```bash
nix shell nixpkgs#rustup
rustup toolchain install nightly
```
Mixing rustup-managed Rust with Nix-provided native libs usually works on
NixOS thanks to nix-ld, but the purest route is the devShell above.

### 6.7 Add a dev shell to the repo itself (optional)
Create `modules/devshell.nix` (auto-imported):
```nix
{ ... }:
{
  perSystem = { pkgs, ... }: {
    devShells.default = pkgs.mkShell { packages = [ pkgs.nixpkgs-fmt ]; };
  };
}
```
Then `nix develop /etc/nixos`. This is separate from the OS build.

## 7. Isolation

From lightest to heaviest:

1. **Ephemeral CLI** — `nix shell` / `nix run` / `nix-shell -p`. Per-command
   environment, nothing persists.
2. **Project dev shell** — `nix develop`. Per-project toolchains and native
   libs. Two projects can’t conflict. This is the sweet spot for Python/C++/Rust.
3. **Pinned project flake** — commit `flake.lock`; the exact nixpkgs revision
   (and therefore every dependency) is reproducible forever.
4. **Build without running** — `nix build` puts a result symlink in `./result`.
5. **Flatpak** (already enabled) — sandboxed GUI apps with their own runtime:
   ```bash
   flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
   flatpak install flathub com.spotify.Client
   flatpak run com.spotify.Client
   ```
6. **Throwaway VM of your system config** — test system changes without risking
   the host:
   ```bash
   nixos-rebuild build-vm --flake /etc/nixos#compulex
   ./result/bin/run-compulex-vm
   ```
7. **NixOS containers / systemd-nspawn** — heavier isolated NixOS instances.
   Not installed by default; enable with (in a host/aspect):
   ```nix
   boot.enableContainers = true;          # provides nixos-container
   virtualisation.containers.enable = true;
   ```
   Then `sudo nixos-container create test --config …` / `start` / `root-login`.
8. **`nix-ld` for foreign binaries** — already on. Lets you run prebuilt,
   non-Nix executables (game binaries, Node addons, rustup, some Python
   wheels) by providing a compatible dynamic loader.

**Containers vs dev shells:** use dev shells to isolate *build tooling*; use
containers/VMs/flatpak to isolate *runtimes, services, or untrusted apps*.

## 8. Store, garbage, and disk

- Everything built lives in `/nix/store` (currently ~34 GB).
- Old generations keep old store paths alive.
- No automatic GC is configured. Run manually (this also deletes old
  generations older than the current one):
  ```bash
  sudo nix-collect-garbage -d
  ```
- More aggressive (only current generation survives):
  ```bash
  sudo nix-collect-garbage -d --delete-older-than 0d   # careful
  ```
- Check what a generation points to:
  `nix-store -q --references /run/current-system`.

## 11. Troubleshooting / gotchas

### 11.1 Home Manager: “Existing file … would be clobbered”
HM refuses to overwrite a file it doesn’t own. Cause: you hand-edited a
generated config (e.g. `~/.config/fish/config.fish`) or a leftover unmanaged
file sits in the way.

Fix:
```bash
# remove/rename the offending file(s) listed in the error, then re-switch
rm ~/.config/fish/config.fish
sudo nixos-rebuild switch --flake /etc/nixos#compulex
```
Or opt into backup/explicit force:
```nix
home-manager.backupFileExtension = "hm-backup";
# or per file: xdg.configFile."x".force = true;
```
**Never edit generated files** — always edit the `.nix`.

### 11.2 Pure evaluation error on an absolute path
`access to absolute path '/home/...' is forbidden in pure evaluation mode`.
Move the file into the repo and reference it relatively, or add `--impure`.

### 11.3 Flake says “path … is not a flake”
You’re pointing `--flake` at a directory without `flake.nix` — e.g. the stale
`/etc/nixos`. Use `/etc/nixos#compulex`.

### 11.4 Rebuild fails, system in mixed state
`nixos-rebuild` sets the profile before fully activating. Just fix the error and
re-run `switch`; or `sudo nixos-rebuild switch --rollback` to go back.

### 11.5 “unfree package” refused
Already handled globally (`nixpkgs.config.allowUnfree = true`). If you add a
new flake input that needs `allowUnfreePredicate`, configure it in that module.

### 11.6 `dirty` warnings
Silenced via `nix.settings.warn-dirty = false` in `core/common.nix`.

### 11.7 Build is slow / wants to redownload
Caches are configured in `flake.nix` (`nix-community`, `nixpkgs`,
`niri-nix`, `noctalia`). For repeated rebuilds, `nixos-rebuild build` first,
then `switch`; the second is cheap.
